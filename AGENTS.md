# InterviewMaster Agent Guide

## Project Shape

- This is a macOS/AppKit Swift app built with direct `swiftc` scripts, not an Xcode project or SwiftPM package.
- The app listens to interview audio, transcribes via Groq Whisper, classifies interviewer utterances, and streams concise answer help.
- Main production path for voice behavior:
  - `Application/VoiceInterviewProcessor.swift`
  - `Infrastructure/Speech/GroqInterviewClient.swift`
  - `Infrastructure/API/AnthropicClient.swift`
  - `Domain/Model/ConversationContext.swift`
  - `Presentation/VoiceInterviewController.swift`

## Build And Verification

- Always run `bash build.sh` after Swift production changes.
- Always run `bash Tests/test.sh` after question detection, answer formatting, latency-routing, role/profile, or conversation-context changes.
- Use `./Scripts/verify-interview-quality.sh` as the default local gate for Codex loops.
- Live API classification checks are optional and must be explicitly enabled with `IM_RUN_LIVE_CLASSIFICATION=1`.
- Audio playback smoke tests are optional and must be explicitly enabled with `IM_RUN_AUDIO_SMOKE=1`; they require the app to have the needed macOS audio/screen permissions.

## Question Detection Rules

- Prefer small, test-backed changes to local guards before changing model prompts.
- Do not promote candidate answer statements such as "I have experience..." into questions just because they contain technical terms.
- Preserve short technical interviewer prompts, comparisons, mixed-language prompts, and contextual follow-ups.
- Keep incomplete utterances buffered instead of answering early when the local signal is weak.
- A clear question that trails off ("...", "and what") is held before any model call and answered without the tail after `bufferedQuestionSilence` (`ConversationUnderstanding.heldQuestion`). A short fragment within `questionContinuationWindow` of a question joins it (`continuedQuestion`). Garbled speech (`looksGarbled`) is never answered: a held question survives it, otherwise the header says `FeedbackCopy.didntCatchThat`.
- When classification and local signals disagree, only override classification if the local signal is strong and covered by tests.
- Add or update deterministic cases in `Tests/test_processor.swift` for every detection edge case fixed.

## Answer Quality Rules

- Answers should be glanceable cue cards: 3-5 short bullets for normal interview answers.
- Avoid intro phrases, disclaimers, and uncertainty hedges when the topic is known.
- For personal/background questions, use the user's background only; do not invent experience.
- Preserve code blocks when the answer includes code.
- Keep answer cleanup in `conversationalDisplayAnswer` deterministic and covered by tests.

## Conversation Understanding Rules

- Shared pure logic lives in `Domain/Model/ConversationUnderstanding.swift` and `ClassifierStreamParser.swift`; the unit tests compile these files directly. `Tests/test_processor.swift` still keeps copies of the processor's own functions, so mirror edits there.
- Latin-script question words (German/French/Spanish) match whole words only, and "was"/"comment" count only as the first word. Substring matching turned "two ", "answer ", "wanna" and "it was" into questions.
- Candidate speech never opens an answer card: long first-person narrative, stalling ("give me a second") and repeat requests are skipped or vetoed. Keep the veto conservative: a real question mark next to interviewer wording (`hasInterviewerFrame`) always wins.
- A fast-path answer inherits the previous topic only when the question refers back to the conversation (`refersBackToConversation`). A concrete new question is answered from its own words (topic `unknown`); topic-specific answer shapes (SOLID, RAG/CAG) apply only to a topic named in the current question.
- The combined classify-and-answer reply is read by `ClassifierStreamParser`. A missing `---` or STATUS header must never drop the answer; an empty answer is recovered with the direct stream on the open card, not shown as an error.
- Replay real sessions from `~/Documents/InterviewMaster/sessions` through the local guards before and after changing detection, and check that no interviewer question becomes newly vetoed.

## Coding Requests

- A spoken task ("write a function that...") streams a `SAY:` block (talking points) followed by `STEP n` blocks (typed code). The code takes the full width of the window and never resizes it; one line above it (`CodeTalkStripView`) shows the first talking point. The full answer and question list open over the code (⌘⌥A, or by themselves when a question is asked) and stay until dismissed, and the code keeps its place. `💻 CODING TIMING` in the log gives the time to the first talking point and first code.
- The panel is `Presentation/Components/CodePanelView.swift`, driven by `Presentation/CodePanelController.swift`. The floating overlay is only the fallback when the main window is hidden.
- The panel keeps a version per request that produced code (keyed by the answer card's turn id), so selecting a card or stepping in the header brings an earlier answer back. `CodingTaskInfo` says what starts a version; `CodingTaskOutcome` says whether it finished. Code that stops early (dropped connection, unterminated fence) is `incomplete`, is never stored as the code on screen, and shows Retry (`retryLastCodingRequest`). The quick-action chips call `requestCodeChange` with the same wording an interviewer would speak, and a unit test keeps every chip classified as a spoken change.
- "Show me that in code" / "an example in code" is a coding request (`CodingRequestDetector.asksForCodeExample`); when it names nothing, the interviewer's previous question (`ConversationContext.lastInterviewerQuestion`) becomes the task. "Easier", "simpler", "cleaner" or "more pythonic" way is an alternative like "another way" and changes the code on screen. A save or an export holds only the latest interview (`interviewStartedAt`, `ExportInterviewUseCase.messages(_:ofInterviewStartedAt:)`): the timeline keeps earlier ones and turn numbers restart at 1.
- Measure wrapped label heights with `NSFont.wrappedHeight(of:width:maxLines:)`: a wrapping `NSTextField` reports one line until it has a layout width. Call `needsLayout = true` when content that drives a frame changes.
- Dictated tasks arrive in fragments. `CodingSessionState` accumulates them and a later fragment refines the same card and panel instead of opening another.
- Once code is on the panel, follow-ups change it: another language, "improve it", "another way", "without slicing", tests (`CodingRequestDetector.followUp` -> `.changeCode`). The prompt then carries the current code plus the request, and the answer opens its own card. A technique demo ("show me sliding window") starts a new task. Ordinary questions stay cue cards with the code as context. Check `/tmp/interviewmaster.out` for the `💻 CODING` lines when a request does not change the code.
- "Write this code" with the task only on the interviewer's screen gets a local hint (capture with the screenshot shortcut), never an invented task.
- Visual QA without network or audio: `python3 Scripts/focus-ui-qa/build-driver.py [output-dir]` builds a driver from the real sources, drives the real delegate with canned questions and code, and writes PNG plus text snapshots (default `.codex-loop/focus-ui-qa/shots`). Read the `.txt` files first; each snapshot also has a `.style.txt` manifest (colors, radii, borders, shadows, fonts per view), and diffing two runs shows exactly which styles a change moved. Runs are byte-identical when nothing changed. `.colors.json` holds every text and glyph with its color and the fills behind it, for `colors.py`; `QA_APPEARANCE=aqua` runs the app under a light system to check the dark pin.

## Design Tokens

- The interview window (answer card, question burst, command bar, code panel) takes every color, alpha, radius, border, shadow, font size, symbol size and delay from `Presentation/Styling/DesignTokens.swift`. Three tiers: `Token.Global` (raw palette and opacity ramp, read only by that file), alias tokens (`Token.Color.textMuted`, `Token.Hue.success.text`, `Token.Radius.md`, `Token.Font.text(.caption, .medium)`), and component styles (`Token.SurfaceStyle`, `Token.ControlStyle`, applied with `applySurface`, `applyGlass` and `HoverButton.apply`). Names read {category}{Property}{Variant}{State}; backgrounds are `bg*`, text `text*`, edges `border*`.
- To change how something looks, change the token, not the view. A new hue or step goes into the token file first; the scale reuses `LayoutConstants` where it already fits (radius 6/10/14, type 11/12/13/15/17).
- Look: macOS desktop widgets (Calendar, Weather). Surfaces are widgets: `Token.Radius.widget` 22, near-opaque graphite (`bgCard`, answer and code) or storm gray (`bgWidget`, question list and CV), a 0.06 white edge (`borderWidget`) and a soft shadow, never a colored outline. What sits an inset inside a widget takes `Radius.inside(widget:)` so corners are concentric. A card's heading is an overline in its hue (the topic in the accent, "Code" in the code hue, the app name in the header) over a 17pt semibold title (`Token.Leading.heading` 1.25, two lines at most). The selected question is a Calendar event: `Token.Selection` wash plus a bar down its leading edge, no ring. Buttons, chips, capsules and notices are filled washes with no border (`borderWidth` 0).
- Color roles. A `Token.Hue` has a `solid` (fills, dots, washes, outlines) and a `text` step (words, glyphs and rings drawn on those washes: a solid hue is too dark to read there). One hue, one meaning: magenta (the Calendar event color) is the app accent, selection and the answer it points at, cyan is code only, green is ready/go, gold is the AI working or needing attention, red is failed/stop, white is neutral. Never borrow a token for another role (a text step as a wash, a scrim as a bar). Washes and outlines come from `hue.tint(_:)` and `hue.edge(_:)`, never `withAlphaComponent`.
- Contrast is APCA Lc, measured, not estimated: body text 75, labels and syntax tokens 60, glyphs, rings and dimmed controls 30. Text is one of four white steps (`textPrimary`, `textStrong`, `textBody`, `textMuted`); there is deliberately no step below `textMuted` (0.66 and 0.55 measured Lc 38-59). Text drawn straight on the glass uses `textBody`. The window pins the dark appearance in `WindowFactory.createMainWindow`, because the glass follows the system appearance and the text is white.
- `python3 Scripts/focus-ui-qa/colors.py <dir>` measures every text and glyph in a driver run against the fills behind it on three glass backdrops (about 0.09, 0.26 and 0.44 gray). It must report nothing below threshold on the dark and typical backdrops. Pairs that fail only on the light backdrop sit on HUD materials the script cannot compute (it treats them as transparent); they are advisories, not proof.
- `Tests/test_design_tokens.swift` fails on a raw color, alpha, font size, corner radius, border width, shadow or delay in the four view files it lists, on a solid hue used as text, on a text step below its threshold, and on a missing dark pin. Add a new interview-window view file to its `guarded` list.
- Typography. Sizes are `Token.Font.Size` (11 capitals only, 12 caption, 13 body, 15 lead, 17 title, 12.5 code) and weights are regular, medium and semibold; emphasis is one weight up, never bold. Wrapped text takes its leading from `Token.Leading` (1.4, and 1.5 for the live answer) through `Token.Text.paragraph`, so a label that wraps is an attributed string, not a plain `stringValue`; measure it with `NSFont.wrappedHeight(..., lineSpacing:)`, because a frame a hair too short drops a whole line. Bullets hang (`Token.Text.bulletIndent`), the answer column is capped near 74 characters (`Token.Measure`), and values that change (positions, counts, latencies, timers) use `Token.Font.digits` so they do not jitter.
- Store text in natural case. Small capitals come from `Token.Text.overline` (uppercased, tracked 0.05 em, tabular digits); phase names are "Queued", not "QUEUED". Use `Token.Text.separator` between the parts of a meta line, the ellipsis character `…`, and curly quotes. Anything that can truncate gets a tooltip with its full value, and nothing clips without an ellipsis.
- `python3 Scripts/focus-ui-qa/type.py <dir>` measures a driver run for all of this (sizes, truncation and tooltips, tracking, tabular digits, line pitch, characters per line, hanging indents, lines that do not fit their frame) and must report 0 findings. `MarkdownRenderer.Style.panel` is the proportional style for prose in the code panel; notes and analysis keep their monospace style.
- Layout. Space groups things before lines do: the gap between groups is at least twice the gap inside one (`Token.FocusLayout`: the strip's label is 6 above its strip and 16 below the card above it; `Token.CommandBar.groupGap` 16 between the bar's groups against `itemGap` 6). Surfaces share one inset (`Token.Space.inset`, 16), text outside a card sits in a frame on the same edge as the text fields inside it (`labelIndent` = inset; a text field draws 2pt inside its frame, so a label at inset - 2 lands 2pt left of the text around it), and order follows importance: answer, question burst, CV strip, bar. Frames are physical left/right; the app is English-only, so RTL mirroring is out of scope.
- Nothing is hidden without a cue or a fallback: scrolling bodies carry an `OverflowCueView` fade; the burst strip switches between columns (side by side), a list (one line each, with its pill) and compact dots by the room the column has; the CV strip takes at most 40% of the body, and never so much that less than `minimumAnswerHeight` of the answer stays in view (`focusBriefingBudget`), and snaps to a height it can fill (two digest lines and points, one, the digest alone); code-panel chips wrap to more rows instead of being dropped; the banner is as tall as its message. Size wrapped labels from measured text plus slack (a frame 0.2pt short drops a whole line) and give capped labels the height of their capped lines (a taller frame draws stale ghost lines).
- `python3 Scripts/focus-ui-qa/layout.py <dir> [<dir>...]` measures a driver run for overlaps, out-of-bounds, hidden content, stray edges (also between text stacked in neighbouring surfaces, and text indented past the inset with nothing in the gutter it leaves), text against a trailing edge, target gaps and group gaps, and must report 0 findings at 1040x680 (default), 760x500 (`QA_WINDOW=760x500 QA_WIDEN=0`), 1600x1000 and 760x900. `Tests/test_design_tokens.swift` also pins the group ratios and that the command bar and header fit 760pt. The driver keeps its own UserDefaults, so it assigns `QA_WIDEN` on every run; compare sizes only across runs with the same knobs.
- Density. The answer is what is read, so it gets the room: the question list takes the height of its rows (`Token.FocusLayout.stripRowHeight` each, stacked, while the code panel is open; `burstHeight` side by side otherwise) and the answer card takes everything else, so the list is never taller than the card. Before the first question there is no list and no label. Say a fact once: the header's capsule holds the activity status on the live tab and the bar's copy shows only on tabs whose header is out of sight (`updateFocusBarActivityVisibility`); a question's state is the pill in its row (no extra dot or spinner); the card says only how its own answer is doing (`Ready · 1.5s`); the app name and the interview profile share the header line instead of a row in the body; the waveform shows only while someone speaks or the AI works. Explain once and briefly: the welcome card and the code panel's empty state are one sentence each, and the follow-up chips appear only when there is code.
- `python3 Scripts/focus-ui-qa/density.py <dir> [<dir>...]` audits a driver run for the same words in two regions at once, a missing activity status, a question list taller than the answer or an answer under 120pt, dead space below the list's rows and empty boxes, and must report 0 findings at the four sizes. Never derive a frame with `insetBy` from a box that can be smaller than the inset: the result is a null rect, and a view at an infinite origin made Auto Layout stretch the window to 1668pt.
- Loading. A wait shows something shaped like what is coming, not a spinner: `SkeletonView` bars (an answer's bullet lines, or `CodeStepSkeletonView` for the first step card) stand exactly where the content will start, the content fades in over them, and nothing moves when it arrives. The highlight passes slowly and stops under Reduce Motion; `Token.Motion.reducesMotion()` is the one check (the QA driver sets it with `QA_REDUCE_MOTION=1`). A wait also says what it is in words (`Domain/Model/WaitProgress.swift`): the card's state reads "Generating", from 4s "Generating · 6s", from 10s "Still generating · 12s", a narrow card keeps just the seconds, and the code panel's subtitle counts the same way. A card is "Generating" until its first words and "Answering" after them.
- Before an answer exists the capsule covers the pipeline: "Transcribing…" once speech has taken `Token.Motion.loadingDelay` (0.2s) to become text (`DelayedActivity`: a shorter wait shows nothing, and one that nothing ends stops showing after 20s) and "Connecting audio…" while a source starts or switches. A briefing that arrives above the answer slides the answer into place (`refreshFocusBodyLayout(animated:)` puts layer animations over final frames: `animator().frame` and implicit animation left the frames unchanged in this hierarchy).
- `python3 Scripts/focus-ui-qa/loading.py <dir> [<dir>...]` audits a driver run for spinners, placeholders without words, status words cut short by their own frame, the answer or first step card moving between its placeholder and its content, motion under Reduce Motion (run the driver once with `QA_REDUCE_MOTION=1`) and a placeholder that does not shimmer without it, and must report 0 findings at the four sizes and in the Reduce Motion run.
- Feedback. Every action is acknowledged where the eye already is: `postFocusNotice` (`Presentation/FocusNoticeController.swift`) puts one line in the header's title row. A confirmation ("Screenshot captured", "Session saved", "Exported ...") goes by itself after 3.5s; something undone ("Cleared 2 screenshots and the pinned code") carries an Undo for 8s instead of asking "are you sure"; an error has a close button and stays until it is dismissed or the thing it is about goes right (`resolveFocusNotice("pipeline")` when a question is heard again). A notice never covers a more important one (`NoticeBoard` in `Domain/Model/FeedbackNotice.swift`). Pipeline errors used to go only to the hidden timeline; `processorDidUpdateStatus` now posts them. Do not add a modal for something the header can say; keep modals for what needs a decision (permissions, API keys, export failure). A notice with a button names what it does: Undo, Show in Finder, Open Settings, Try again, Export.
- The capsule says what is true: "Muted", "No audio", "Connecting audio…", never "Ready" while nothing can be heard. A failed answer says why (`FeedbackCopy.failureReason`) and offers "Try again" while an interview is running; `retryAnswer` fills the same card, or asks for the code again when the card is a coding request. Feedback is words and an icon, not colour alone, and VoiceOver hears it (`announceForAccessibility`; the copy buttons announce "Copied"). The QA driver has no audio device, so `qaAudioPresentation` names what the window would have.
- `python3 Scripts/focus-ui-qa/feedback.py <dir> [<dir>...]` audits a driver run for a capsule that says something false, an error with no words, icon or close button, a confirmation with a close button, an error covered by a confirmation or left after a question was heard, an Undo that is missing, a failed card without a reason or a retry, and notice words cut short; it must report 0 findings at the four sizes and in the Reduce Motion run.
- Writing. One voice: plain, calm, no "please", "oops" or exclamation marks, and contractions ("Couldn't") in errors. The window's own text is sentence case (names as written: Settings, TypeScript, CV); alert titles are sentence case; buttons and menu items in system alerts and menus keep the platform's Title Case. Buttons start with a verb ("Start interview", "Try again", "Show latest", "Try another way", "Use TypeScript") or name a place (Context, Timeline, Practice, Code, Settings). One word per idea: "Try again" (never "Retry"), "screenshot" (never "shot"), "Questions" (the strip's label; "question burst" is only a code name), "CV" (never "resume" in the window or Settings), "System audio", "End interview", "Interview Master" (never "Interview Assistant"), and shortcuts as glyphs (⌘⇧M), never "Command-Shift-M". An error says what failed and then the fix on the line itself ("Couldn't transcribe. Check your connection."), or carries the fix as a button beside it ("Groq API key rejected" with Open Settings; "Couldn't capture the screenshot" with Try again; "Couldn't save the session" with Export); when nothing can be done it says what may have been lost on hover (`FeedbackCopy.lastQuestionMissed`). Never "Something went wrong". The header notice, the failed card and the code panel read the cause of a failure from one place (`FeedbackCopy.cause(of:)`), so they never name two causes for one failure; all notice wording that is not a one-off lives in `FeedbackCopy` (`nothingToAnalyze`, `sessionSaved`, `cleared`, ...) where it is tested and where the QA driver posts the same strings. An empty state says what goes there and what to do ("Start the interview and each question the interviewer asks gets a short answer here"). A topic the classifier names in camelCase ("ragCag", "llmEvaluation", "csharp") is shown through `TopicTitle.display` in the card title, the timeline pill and an export ("RAG and CAG", "LLM evaluation", "C#"), never `capitalized`; add a new acronym or product name to its `words` table. The mute button's hover says what a click does ("Muted. Click or press ⌘⇧M to unmute."). A notice line stays under about 48 characters so it fits beside the busiest capsule at 760pt wide; the rest goes on hover.
- `python3 Scripts/focus-ui-qa/writing.py <dir> [<dir>...]` reads the words a driver run laid out and reports banned vocabulary, a second word for a term, a button that does not start with a verb, Title Case mid-sentence, a topic that does not read as words, and an empty state that does not say how to fill it; it must report 0 findings at the four sizes. `Tests/test_design_tokens.swift` scans the files that hold the window's copy for the same vocabulary rules (`bannedCopy`), so add a new copy-holding file to its `copyFiles` list. The interviewer's questions, the answers and the CV are content, not copy, and are left alone.
- Other screens (Practice, Settings, Timeline messages) still hold their own values; move them onto the tokens when they are next touched.

## Latency Optimization Rules

- Optimize for user-visible first useful answer text, not only the internal `latency=...ms` card-start metric.
- Track and compare `card_start_ms`, `first_answer_text_ms`, and `answer_complete_ms` from logs when available.
- Target first useful answer text under about 1000ms after question detection for clear questions.
- It is acceptable to show a short provisional answer first, then append or refine the same answer if the interviewer adds more context.
- Avoid duplicate answer cards for continued interviewer speech; update the active answer when it is clearly the same question.
- Model experimentation is allowed for this goal. Codex may try faster classification/answer models, split-model routing, smaller token budgets, and prompt changes, provided quality safeguards and tests remain intact.
- Do not fake speed by hiding the spinner or changing labels while the answer body is still empty.

## Automation Safety

- Do not auto-commit from local loops. Leave reviewable diffs for the user.
- Do not hardcode or print API keys. Keys live in `~/.interview-master-keys` or matching environment variables (`GROQ_API_KEY`, `XAI_API_KEY`, optional `ANTHROPIC_API_KEY`). See `interview-master-keys.example`.
- Do not introduce new production dependencies unless the user explicitly asks.
- Respect existing dirty worktree changes; avoid unrelated refactors.
- Keep generated loop artifacts under `.codex-loop/`.
